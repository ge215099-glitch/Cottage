# 重做实施计划

> 本文为第一轮实施计划。第二轮已按用户要求改为默认右侧详情栏、取消对话搜索，当前界面规范以 [前端方向](frontend-direction.md) 为准。

日期：2026-11-18。阶段 A–C 的第一轮实现已落地，阶段 D 已完成桌面宽屏与浅/深主题检查，窄窗口、真实接口和打包仍待验收。以下保留实施路径；具体结果以 [实现记录](implementation-status.md) 为准。

## 1. 复用与替换范围

| 区域 | 工作方案 |
|---|---|
| `src/core` | 优先复用；修正压缩后请求和人设内容等已确认行为问题 |
| `src/main` | 复用数据库、Provider、导入导出、密钥与桌面生命周期；拆解有问题的服务边界 |
| `src/shared`、`src/preload` | 尽量保留 API 契约；确有新增能力时同步 schema、handler、类型和测试 |
| `src/renderer` | 重建布局、页面层级、会话入口、按需面板与样式；不要只给旧结构换 CSS |
| 构建配置 | 先沿用已安装技术版本，避免界面重做与大规模升级同时发生 |
| 测试 | 保留纯业务与数据回归；旧 UI 契约按新行为改写 |
| 旧文档与校验 | 取可复用产品规则；删除或改造针对旧标签数、入口、文案的约束 |
| `FrontendDemo` | 保持原参考文件；从中提炼视觉与交互，不直接作为生产业务层 |

## 2. 数据隔离与迁移

1. 新源码落在本工作区，建立独立版本记录，记录来源提交与未提交差异。
2. 按文件范围迁入所需源码、配置和测试，不整目录复制 node_modules、out、dist、日志、缓存或报告附件。
3. 开发版使用独立 Electron userData。调整名称/应用身份时，同时核对 main 启动、单实例锁、打包 appId 和快捷方式。
4. 保留数据库 001–004 迁移编号；新增字段通过追加迁移实现，不修改已发布迁移。
5. 如需导入旧数据，先在应用关闭后备份数据库、可能的 WAL/SHM 与 avatars；在副本演练迁移，校验角色、会话、摘要和密钥可用性。safeStorage 密文不是可跨机器通用的明文凭据。
6. 旧 `panelOpen`/`panelTab` 不得令新版恢复为默认四标签右栏；兼容读旧字段，按新版行为忽略/迁移 UI 偏好，不因此让整份有效设置回退。

## 3. 开发顺序

### 阶段 A：独立基础与业务回归

迁入可复用层，建立隔离数据目录，确认开发/构建入口。先复现并修复调研列出的高优先级问题：自动压缩后真正发送新 Prompt；取消不能只改变前端状态。确认人设描述、模型上限和错误反馈的契约。

完成条件：类型检查、业务测试和构建通过；测试使用临时库或内存库，不接触真实数据和真实模型。

### 阶段 B：聊天主界面

实现左栏、顶栏、空态、消息流、输入区与模型选择。以当前文档中的 demo 风格为准。实现直接接入 `window.cottage`；视觉测试使用隔离数据库中的明确预览内容，不在生产入口静默兜底成假聊天。

拆分建议：

```text
renderer/
  app/          AppShell、路由/视图、启动与全局事件协调
  features/
    chat/       消息、输入、模型选择、会话动作
    characters/ 角色库、详情、编辑
    memory/     摘要、恢复、整理进度与技术明细
    settings/   模型连接、人设、用量、偏好
  components/   通用菜单、弹窗、图标、空态
  styles/       tokens、基础样式与布局
```

不为了目录形式迁移稳定代码。关键是业务动作、数据加载与视图避免再次集中到一个千行 App。

完成条件：默认无右栏、中文输入法下发送正确、滚动和草稿稳定；模拟界面测试与真实 Electron 联调分开报告。

### 阶段 C：功能收纳与全链路

接入角色库与导入、角色详情、新会话、人设与 API 连接、用量、导出、对话设置和记忆面板。确保精简后每个原功能都有明确入口。

全局流式事件只建立一组生命周期明确的订阅，卸载正确清理；根据 conversationId/streamId 路由更新，避免快速切换会话时串消息。设置与面板的开关不触发重复订阅。

完成条件：从导入角色、配置模型到发送、停止、重生成、整理、恢复和导出闭环走通；真实请求只在用户明确要求且配置好时使用。

### 阶段 D：视觉验收与桌面交付

在真实窗口查看浅/深主题、不同尺寸、长内容、菜单边缘、焦点和错误态；验证开发启动与生产构建两个入口。需要交付安装包时，再检查原生 SQLite 模块、独立数据目录与启动行为。

## 4. 测试策略

| 测试 | 重点 |
|---|---|
| core/服务回归 | 角色卡往返、Prompt、人设、压缩后实际请求、SSE、空响应、停止、token 估算 |
| 数据回归 | 迁移幂等、摘要与归档原子性、恢复、截断后的摘要失效、置顶不刷新排序时间 |
| UI 行为 | 默认无右栏、菜单功能可达、草稿恢复、输入法、模型继承、人设选择、错误后重试 |
| 事件生命周期 | 切换会话不串流、关闭面板不丢任务、无重复订阅、旧流不覆盖新流 |
| 实际窗口 | 排版、滚动、菜单定位、窄屏、深色、焦点和触控可达性 |
| 桌面冒烟 | Electron 能开库、迁移、注册 IPC、建窗口；原生模块与打包单独验证 |

不要用匹配文档段落或按钮数量的测试替代业务验证。保留 API 结果错误分支和密钥脱敏测试；不为文档变更增加镜像断言。

## 5. 后续需随工作更新的事项

- 默认无常驻右栏是本轮提出的简化方案；若用户希望保留精简右栏，应据反馈调整，不把本提案写成永久冻结约束。
- 目前维持单角色、文本聊天和本地 BYOK；多角色群聊、云同步、语音与附件不在这轮迁移范围。
- 是否必须兼容用户现存全部真实会话，应在真正迁移数据前结合数据副本确认，不能仅凭源码结构宣称兼容完成。
- 更新进度时说明实际完成的阶段与验证结果，不能将原型完成写成可打包软件完成。

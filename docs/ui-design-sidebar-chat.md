# Cottage 界面与交互设计：应用外壳 + 左侧栏 + 对话列表

> 版本：v1.0（MVP）
> 上游基线：`docs/product-design.md`（v1.0）。本文只细化**布局与交互**，不新增产品能力，不修改数据模型。
> 风格基准：ChatGPT Web（参考截图 "Chat prompts" 页）——左栏固定分组导航 + 列表区，主区极简留白，操作按需出现。
> 一句话原则：**常驻界面只留下"去哪里"和"输入框"；其余动作都藏在悬停/菜单里。**

---

## 1. 设计原则（约束后续所有细节）

| 编号 | 原则 | 具体含义 | 反面例子（禁止） |
|---|---|---|---|
| P1 | 一屏一个主动作 | 侧栏顶部只有 1 个实心按钮「新对话」；输入框右下只有 1 个发送/停止按钮 | 主区右上排 6 个图标按钮 |
| P2 | 低频动作隐藏 | 重命名 / 删除 / 导出 等进入 `⋯` 菜单，不常驻 | 每条对话右边常驻铅笔+垃圾桶图标 |
| P3 | 悬停才出现，出现即稳定 | `⋯` 只在行悬停/聚焦时淡入，占位恒在，行内容不位移 | 悬停后标题被挤动换行 |
| P4 | 状态靠填充，不靠描边 | 悬停=一层浅填充，选中=更深一层填充 + 左侧 2px 强调条 | 到处 1px 边框、胶囊高亮块 |
| P5 | 强调色只给三处 | 「新对话」按钮、生成中的光标/停止、上下文占用告警 | 导航图标着色、列表项着色 |
| P6 | 中文优先排版 | 列表项/标题按中文设定字号与行高，数字与英文不跳字重 | 直接套英文设计稿的 13px/1.2 |
| P7 | 不打断书写 | 任何侧栏操作都不得改变输入框内容与焦点，除非用户主动切换会话 | 点重命名导致输入框清空 |
| P8 | 信息密度可调 | 窗口变窄先折叠侧栏文字，再收起导航，而不是挤压主区 | 三栏同时被压成 200px |
| P9 | **不留头像位**（角色库除外） | 消息、对话列表、空态、右栏角色卡一律不加头像，身份靠**名字文本**（12px 次要色）与位置表达。**角色库是卡片网格，有图**——那是"逛"的界面，见 §3 勘误 | 列表项前一行彩色圆点、消息旁一列头像 |
| P10 | **只有拉出/收起，没有中间宽度** | 左右栏各自只有「展开 / 收起」两态，不做拖拽调宽 | 边缘 4px 调宽命中区 + 宽度记忆 + 最小宽度兜底 |

## 2. 整体布局骨架

三栏结构。左侧栏常驻，主区占满剩余，右侧详情栏**默认收起**（对应 `product-design.md` 3.6 的 9 项职责——它内容多，但入口只允许一个）。

```
┌──────────────┬────────────────────────────────────────────┬─────────────┐
│ 左侧栏 Sidebar│  主区 Main                                  │ 详情栏(可收起)│
│ 展开 260px    │  flex: 1  (min 480px)                      │ 展开 320px  │
│ 收起 → 56px   │                                            │ 收起 = 不占位│
└──────────────┴────────────────────────────────────────────┴─────────────┘
```

> **宽度不可拖拽**：左栏与右栏都只有"拉出（展开）/ 收起"两种状态，没有中间宽度。理由：可拖宽会带来一堆边界问题（记忆值、最小宽度、内容回流），而收益只是"再宽一点"，对列表型内容并不值。

### 2.1 左侧栏内部结构（上固定 / 下滚动）

关键点：**只有对话列表区滚动**，上面的固定项永远不动（对应你要求"上面是固定项，下面是对话列表"）。

```
┌───────────────────────────────────┐

│   Cottage  [⌘] 折叠钮        [☰]  │

│ ② 主操作区 (不滚动)                │

│   [ 🔍 搜索对话…        ⌘K ]       │
├───────────────────────────────────┤
│ ③ 固定导航 (不滚动)                │
│   角色库          ← 当前视图       │
│   人设                             │
│   设置                             │
│   （无「对话」项：回到对话靠点      │
│     会话行或新建一个，见下方勘误）  │

│ ④ 对话列表标题行 (32px, 不滚动)    │
│   对话                    [＋]     │
├───────────────────────────────────┤
│ ⑤ 对话列表 (flex:1, 唯一滚动区)    │
│   ┌ 已置顶（有置顶时才出现）────┐  │
│   │ 标题…                      ⋯ │  │ ← 悬停/聚焦才显示 ⋯

│   │ 标题…                      ⋯ │  │

│   │ 标题…                      ⋯ │  │

│ ⑥ 底部固定 (不滚动)                │
│   默认人设 · ASMobbin      [⋯]      │

```

### 2.2 主区结构

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏 48px：会话标题（可点击行内重命名） …  [⧉ 详情]           │
├──────────────────────────────────────────────────────────────┤
│ 消息流（滚动，最大内容宽 720px 居中，左右留白自适应）          │
│                                                              │
│   角色气泡 ───────────────────────────────────               │
│   用户气泡 ───────────────────────────────────               │
│                                                              │
│ 空态（无消息时）：角色头像 + 名称 + 开场白 + 输入框           │
├──────────────────────────────────────────────────────────────┤
│ 输入区（不滚动，底部居中，最大宽 720px）                       │
│   ┌────────────────────────────────────────────────────┐     │
│   │ 多行输入（1→8 行自适应）                           │     │
│   │  [模型 pill]                        占用 62% (↑)   │     │
│   │                                            [ ↑ ]   │     │

**主区顶栏只有 2 个元素**：会话标题、详情栏开关。导出 / 删除会话 / 改参数全部不放在这里（导出与删除在侧栏 `⋯` 菜单，改参数在详情栏）。这是 P1 的直接落地。

## 3. 左侧栏 ①–⑥ 逐块规格

| 区块 | 高度 | 内容 | 交互 |
|---|---|---|---|
| ① 品牌行 | 56px | `Cottage` 文字标 + 折叠钮 | 双击品牌行 = 折叠/展开；折叠钮 `title="折叠侧栏 (⌘B / Ctrl+B)"` |
| ② 主操作 | 88px | 「新对话」全宽实心主按钮；「搜索对话」行 | 新对话 `⌘N / Ctrl+N`；搜索 `⌘K / Ctrl+K`，聚焦后列表即时过滤 |
| ③ 固定导航 | 4×36px | 角色库 / 人设 / **API Key** / 设置（**刻意没有「对话」**，见下方勘误） | 单击切换主区视图；当前项 = 浅填充 + 左侧 2px 强调条；**图标不着色**；视图是对话时没有任何当前项 |
| ④ 列表标题行 | 32px | 文案「对话」+ 右侧 `＋`（与 ② 同功能，供列表区就近新建） | `＋` 悬停才淡入；点击等价于「新对话」 |
| ⑤ 对话列表 | flex:1 | 两段：`已置顶`（可选）+ 其余全部 | 唯一滚动容器；行悬停出 `⋯`（第 4 节详述）；**点行总是切回对话视图** |
| ⑥ 底部 | 56px | 文本「默认人设 · ASMobbin」 | 点击打开人设快速切换（下拉，非弹窗）；`⋯` → 人设管理/设置。**不留头像位**（见 P9） |

**导航项说明**（为什么是这 4 个）：按 `product-design.md` 2/3.2，Cottage 的实体有 Character / Persona / Provider / Conversation。导航只承担"去别处"，所以：

| 导航项 | 为什么单列 |
|---|---|
| 角色库 / 人设 | 实体，各有独立的增删改 |
| API Key | Provider 与密钥的增删改是一整块独立工作，挤在设置页里会让设置变成配置大杂烩 |
| 设置 | 只留全局默认、生成与行为、诊断 |

**Conversation 不单列导航**——它已经在正下方的列表里，再放一个「对话」等于同一个动作两个入口。

**折叠态（56px）**：只保留「新对话」图标与 4 个导航图标。会话标题、分组标题、搜索文字全部隐藏，会话行退化为**纯文字行**（无头像可退），`⋯` 仍可通过右键或长按触发，展开靠品牌行的折叠钮或 `⌘B`。

> **勘误（v1.4 修订）：新增导航项「API Key」，设置页不再管 Provider 与密钥**
>
> 起因：设置页当时是"配置大杂烩"——Provider 列表、常驻的添加表单、全局默认、生成行为、
> 诊断全挤在一屏里，其中 Provider 那一块还占了将近一半的高度。而"我这把 Key 是什么时候
> 建的、上次用是什么时候"这类**主动来查**的问题，在设置页里没有任何落点。
>
> 改法：
>
> 1. **新增 ③ 导航项「API Key」**，导航从 3 项变为 4 项。
> 2. **Provider 与密钥的增删改整体搬到「API Key」页**，形态改为**列表 + 弹窗**：
>    页面上不常驻表单，添加/编辑都在弹窗里完成。列表列为
>    名称 / 状态 / Key / 创建日期 / 最新使用日期。
> 3. **设置页只留三段**：全局默认（聊天/压缩默认 Provider）、生成与行为、诊断。
> 4. **明文配置包导出入口删除**（详见 `tech-stack.md` 6.4 规则 5）。
> 5. 「无可用 Provider」的引导文案从「去设置」改为**「去 API Key」**：
>    提示的落点必须是能解决问题的那一页，否则用户按提示走过去只会更困惑。
>
> 两条随之确立的硬规则：
>
> - **密钥列只渲染固定掩码**（`sk-••••…`），不含真 Key 的任何片段——
>   renderer 本来就只拿得到 `hasKey: boolean`（`tech-stack.md` 6.4 规则 1），
>   所以掩码不可能泄露，也不可能被当成真值复制出去。
> - **「最新使用日期」是派生值**，来自消息元数据里的 `providerId`，
>   不是 `providers` 表的列。从未用过显示「—」。

> **勘误（v1.0 修订）：去掉「对话」导航项；「新对话」改为三步向导**
>
> 起因是实际使用暴露的两个问题：
>
> 1. ③ 里那一项「对话」与正下方的会话列表**重复**——同一个动作两个入口；
> 2. 更要紧的是，**在角色库 / 人设 / 设置页点会话行不会跳回对话**。原因有两层：
>    `selectConversation` 只换了会话、没切视图；它还写了"id 相同就 return"，
>    于是在设置页点**当前已选中**的会话会彻底没有任何反应。
>
> 改法：
>
> 1. **③ 固定导航从 4 项减为 3 项**（角色库 / 人设 / 设置），导航只承担"去别处"。
>    **回到对话 = 点会话行，或新建一个**。视图是对话时导航没有当前项（无 `aria-current`）。
> 2. 点会话行**总是**切回对话视图——包括"点的就是当前会话"这条路径。
> 3. 「新对话」不再一键建库，改为**三步向导**（下表）。
>
> **新建对话向导：选角色 → 选人设 → 选 Key，每一步都要显式确认**
>
> | 步 | 内容 | 预选 | 该步缺数据时 |
> |---|---|---|---|
> | 1 | 选角色：角色库列表（名称 + 描述） | 无。从角色卡上的「新对话」进来时**跳过本步** | 「去角色库导入」 |
> | 2 | 选人设：你是谁 | 全局默认人设 | 「去创建人设」；人设可选，仍可继续 |
> | 3 | 选 Key：**启用的** Provider（名称 + 默认模型 + 是否已存密钥） | 设置里的默认聊天 Provider | 「去设置」，且「开始对话」禁用 |
>
> 为什么不沿用"一键创建"：角色、人设、Provider 这三件事过去由应用替用户猜
> （`activeCharacter ?? characters[0]` 加全局默认 Provider），用户既看不见也改不了，
> 建错了还得进设置返工。向导把三个选择摆到明面上，同时**预选值是可见的**，
> 正常路径一路确认即可，不需要为了通过而多点。
>
> 交互细节：Esc 或点遮罩关闭；建库失败**留在向导内**显示原因（不丢用户已选的三项）；
> 提交期间按钮禁用防重复提交；停用的 Provider 不出现在第 3 步；
> 每一步的缺数据提示都给出**明确的下一步动作**，而不是让按钮静默变灰。
>
> **早期交互参考件 `demo/index.html` 已删除（v1.3）**：它当年是需求方给的交互样本，
> 与本文档的旧版一致（第 ③ 区 4 项、无新对话向导、角色库是文字列表）。
> 后来参考件与实现分叉，留着只会被当成第二份规格，因此**参考件与它的校验脚本
> 一并删除**，由本文档 + 应用实现 + 测试作为唯一真相。

> **勘误（v1.1 修订）：角色库改为卡片网格，P9「不留头像位」收窄到消息相关界面**
>
> 起因：角色库是唯一一个"逛"的界面，角色卡的价值一大半在卡面图上，一行一行的
> 文字列表既认不出角色、也没利用起图片。改成 **2:3 竖版卡片网格**（上面图片、下面名字）。
>
> 因此 P9 必须收窄——它原本写的是"任何位置的头像位"（本文档 P9、验收项 25、
> 第 14 节"明确不做"，以及 `ui-design-conversation.md` 的对应条目）。
> 新口径：
>
> | 界面 | 是否用图片 | 理由 |
> |---|---|---|
> | 角色库卡片、角色详情弹窗 | **用** | 浏览型界面，图片是最快的识别手段 |
> | 消息流、会话列表、空态、右栏「角色」标签、底部人设行 | **不用** | 阅读型界面，身份靠名字文本足够，加头像只会增加噪音（P1） |
>
> 具体规格：
>
> - **卡片**：`grid` 自适应列宽（`auto-fill` + 最小 148px），`aspect-ratio: 2/3`，
>   图片 `object-fit: cover`；名字 13px 单行省略（两行会让网格行高不齐）；
>   **不显示描述**——描述挂在该卡片的 `title` 悬停提示上，信息不丢但不占视觉。
> - **没有图片**：**纯灰色色块**占位。不留空洞，也**不放任何图标**——放个占位小人
>   等于引入了"默认头像"，与 P9 冲突。
> - **点卡片 → 详情弹窗**：展示大图、名字、tags、描述/性格/场景/开场白（空字段不占位），
>   底部是全部动作：新对话 / 编辑 / 收藏 / 导出 / 删除（删除用危险色）/ 关闭。
>   Esc 与点遮罩都能关；执行"新对话 / 编辑 / 删除"后弹窗自动关闭，避免用户以为没生效。
>   弹窗只记 id、角色对象从 props 实时推导，这样收藏后不会显示旧状态，
>   角色被删掉时弹窗也会自己关掉。
> - **图片通道**：DB 存相对路径（如 `avatars/lin-wan.png`），界面用自有协议
>   `cottage-avatar://local/…` 取图；CSP 的 `img-src` 相应加了 `cottage-avatar:`。
>   主进程侧 handler 会把 URL 解析到 `<userData>/avatars/` **之内**并拒绝目录穿越、
>   非白名单扩展名与畸形编码（见 `src/main/avatars.ts`，那一层有专门的单元测试）。
>   放行的是**协议**而不是 `file:`，所以 renderer 仍然读不到任意本地文件。
>
> **PNG 导入已实现（v1.2 补记）**：`导入角色卡` 现在同时接受 PNG 与 JSON。
> PNG 卡的 JSON 藏在 `chara` / `ccv3` 文本块里（base64），图片本身即卡面图，
> 导入时整张 PNG 会存进 `<userData>/avatars/<角色 id>.png` 并写回 `avatar_path`，
> 所以导进去就能在卡片上看到图，不再走灰色占位块。解析规则与边界
> （`ccv3` 优先、多块逐个尝试、压缩块明确报错）见 `product-design.md` 3.2。
>
> **PNG 导出已实现（v1.3 补记）**：详情弹窗里的「导出」不再直接导出，而是**开一个
> 两项菜单**让用户选格式（`导出为 JSON` / `导出为 PNG 卡`）——格式在应用里选，
> 而不是在系统保存对话框的「保存类型」下拉里选：那个下拉在不同平台表现不一致，
> 而且 PNG 卡要求角色有卡面图，没有的话菜单项直接置灰并写明原因，比"挑完路径
> 才被告知导不出来"清楚得多。菜单用的是既有那一个菜单实例（锚点就是按钮本身）。
> 选完格式才弹原生保存对话框；用户取消不算失败，提示文案要说清这一点。
> 多层浮层的 `Esc` **只关栈顶那一层**：菜单开着时 `Esc` 收起菜单，底下的详情弹窗
> 留着，再按一次才关弹窗。

## 4. 核心交互一：会话行与 `⋯` 菜单（重点）

### 4.1 行的状态矩阵

| 状态 | 触发 | 行外观 | `⋯` 按钮 | 说明 |
|---|---|---|---|---|
| 默认 | — | 透明背景，标题 1 行省略 | 透明度 0（**占位保留**，宽 28px） | 不预留会使悬停时标题横跳（违反 P3） |
| 悬停 | 指针进入行 | 背景 `--surface-hover`，圆角 8px | 透明度 1，淡入 120ms | 指针进入 `⋯` 区域不改变行状态 |
| 选中（当前会话） | 点击行 | 背景 `--surface-active` + 左侧 2px 强调条 | 悬停时同样出现 | 与"悬停"叠加时以选中色为准，只加深不换色 |
| 键盘聚焦 | Tab 到达 | 2px 焦点环（内缩，不改变尺寸） | 透明度 1 | 焦点环只在键盘导航出现，鼠标点击不显示 |
| 生成中 | 该会话正在流式输出 | 标题右侧 8px 呼吸圆点 | 与默认一致 | 圆点用强调色；流式结束才重排列表顺序（见 5.5） |

> 表格里没有"拖拽中"状态：列表不做拖拽排序（见第 14 节）。

行规格：高 36px，左右内边距 10px（收起态为 0 并居中），标题 13px/20px、最多 1 行省略号；**行内只有标题与 `⋯`，没有头像**（P9）；`⋯` 按钮 28×28px 命中区（视觉图标 16px），`aria-label="更多操作"`。

### 4.2 悬停 → 菜单的交互时序

> 说明：本节描述的是**一次悬停与开菜单的先后顺序**（t0→t3），不是产品功能，界面上也没有对应的控件。

```
t0    指针进入会话行
       ├ 行背景淡入 120ms
       └ ⋯ 淡入 120ms（占位已存在，无位移）

t1    指针移到 ⋯ 上（或已点击）
       ├ 行保持悬停态（⋯ 属于行，不算离开）
       └ ⋯ 背景变 --surface-hover（自身也有悬停反馈）

t2    点击 ⋯
       ├ 菜单在 ⋯ 右下展开（见 4.4 定位规则）
       ├ ⋯ 变为打开态（背景 --surface-active）
       └ 行保持悬停态直到菜单关闭

t3    菜单打开期间
       ├ 指针可自由移入菜单
       ├ 若指针移回并停在同一行 → 菜单不关闭
       └ 若指针移到**另一行**的 ⋯ 并点击 → 直接切换菜单锚点（不闪断）
```

延迟策略：关闭加 **180ms 宽限期**（指针离开行/菜单后 180ms 内回到任一者则不关闭），打开无延迟。目的是消除"手抖丢菜单"。

### 4.3 菜单项

```
┌──────────────────────┐
│ 重命名            F2 │
│ 置顶/取消置顶        │
│ ──────────────────── │
│ 删除                 │  ← 文案用危险色
└──────────────────────┘
```

| 菜单项 | 行为 | 备注 |
|---|---|---|
| 重命名 | 行内变输入框（见 4.6），**不弹窗** | 也支持双击会话标题直接进入 |
| 置顶 / 取消置顶 | 置顶行固定到列表最上方「已置顶」段；菜单文案随状态在 `置顶` / `取消置顶` 间切换 | **MVP 必做**，落库为 `conversations.pinned_at`（见 `docs/ui-design-conversation.md` 第 9 节），不允许只做 UI |
| 删除 | 打开确认对话框（见 4.7） | 唯一破坏性操作，必须二次确认 |

**刻意不放进菜单的**：导出（放详情栏 3.6-⑧）、复制 ID、打开所在数据库（开发者项，放设置页）、导出 JSON。菜单项**超过 5 条就砍**，否则违反"不要一个界面乱七八糟的按钮"。

### 4.4 菜单定位与边界

- 默认对齐 `⋯` 的右下角（`align: start`）；若右溢出视口 → 右对齐；若下溢出 → 向上展开；菜单宽 200px，高随项数。
- 菜单挂在 `body` 的 Portal 层，不被侧栏 `overflow: auto` 裁切。
- 视觉：`--surface-overlay` 背景、1px `--border-subtle`、圆角 10px、阴影 `0 8px 24px rgba(0,0,0,.12)`（深色主题用 `.32`）、项高 32px、字号 13px、左右内边距 10px。

### 4.5 关闭与焦点回收

| 事件 | 结果 | 焦点去向 |
|---|---|---|
| `Esc` | 关闭 | 回到该行的 `⋯` 按钮 |
| 点击菜单外任意处 | 关闭 | 保持浏览器默认（点到谁是谁） |
| 滚轮 / 列表滚动 | 关闭 | 会话行（不出意外焦点） |
| 窗口失焦 / 视图切换 | 关闭 | — |
| 选中任一菜单项 | 立即关闭再执行动作 | 按动作决定（重命名 → 输入框；删除 → 确认框） |

菜单内键盘：`↑/↓` 移动、`Home/End` 首尾、`Enter` 激活、`Tab` 关闭菜单并正常 Tab、菜单项数 ≥ 8 时才启用首字母跳转。实现用 `role="menu"` / `role="menuitem"`，打开时焦点进入第一项。

### 4.6 行内重命名

```
┌───────────────────────────────────┐
│ ▌[ 标题输入框____________ ]    ⋯  │
└───────────────────────────────────┘
```

- 进入：`⋯ → 重命名`、`F2`（行聚焦时）、双击标题。
- 输入框接管整行宽度（右侧 `⋯` 暂时隐藏），文本**全选**，光标在末尾。
- `Enter` 或失焦 → 提交；`Esc` → 取消并回滚原标题。
- 空标题 / 纯空白 → 不提交、不报错弹窗，输入框抖动 120ms + 边框转危险色，保持编辑态。
- 标题长度上限 80 字，超出即截断输入（不等到提交才报错）。
- 提交成功后：行显示新标题；若列表按 `updated_at` 排序，**重命名不改变排序**（避免刚改完名就跳走）。
- 同步：主区顶栏标题实时更新；若该会话是当前会话，写入 DB 走 `conversations.title`。

### 4.7 删除确认

```
        ┌──────────────────────────────────────┐
        │ 删除对话？                            │
        │ 「夜巡酒馆的第三夜」                   │
        │ 共 214 条消息，其中 3 段摘要将一并删除。│
        │ 此操作不可撤销。                       │
        │                     [取消] [删除]     │
        └──────────────────────────────────────┘
```

- 必须显示：标题、消息条数、将被级联删除的摘要段数（`summaries` 覆盖区间，见 `product-design.md` 4 约束）。
- 「取消」为默认聚焦项，`Enter` 默认**不**删除；`Esc` 取消。
- 确认后：删除 `messages` / `summaries` / `conversations` 行（一个事务，失败则回滚且不改变 UI，见 3.8）。
- 删的是当前会话 → 焦点交给相邻会话（优先下一条，无则上一条）；列表空了 → 进入空态页。**不弹"删除成功"提示**（P1），仅当进入空态时才出现空态引导。
- 生成中删除：先中断流式（`AbortController`），再删除，避免残留写入。

### 4.8 空态与列表为空

列表为空（没有会话）时，⑤ 区不显示分组标题，改为单行灰字："还没有对话　新建一个 →"（点击 = 新对话）。不放大插画、不放引导长文。

## 5. 核心交互二：列表本身

### 5.1 分组规则（不按时间分组）

列表**只有两段**，且第二段不带标题：

| 段 | 判定 | 段内排序 |
|---|---|---|
| 「已置顶」 | `pinned_at IS NOT NULL`（仅当存在置顶会话时才出现这一段） | `pinned_at DESC` |
| （无标题）其余全部会话 | `pinned_at IS NULL` | `updated_at DESC` |

- **不做「今天 / 昨天 / 前 7 天 / 更早」的时间分组**：会话列表是"最近用过的在最上面"的有序队列，时间分组只增加了标题占位与视觉噪音，检索交给 `⌘K` 搜索。
- 「已置顶」段标题 12px、`--text-tertiary`、高 28px、`position: sticky; top: 0`（列表内吸顶）；无置顶时**整段标题不渲染**，列表直接以会话行开始。
- **置顶不修改 `updated_at`**：取消置顶后该会话必须回到它按 `updated_at` 该在的位置（见 `docs/ui-design-conversation.md` 9.1）。

### 5.2 搜索过滤

- 触发：② 的搜索行、`⌘K / Ctrl+K`。
- 过滤范围：会话标题（本期）；输入 2 字以上时才发起（避免全表抖动）。
- 命中的**匹配片段**用强调色加粗，其它不变。
- 过滤态下：不渲染「已置顶」段标题，改为顶部一行 "找到 N 个对话"（置顶项仍排最前）；列表项仍保留 `⋯`（重命名/删除在过滤态同样可用）。
- `Esc` 清空并退出过滤；无结果时显示 "没有匹配的对话"。

### 5.3 会话行点击语义

- 单击行（非 `⋯` 区域）→ 切换当前会话。**无加载遮罩**，先渲染本地已存消息，流式未完成的会话继续流。
- 已在当前会话时单击 → 无操作（不重新加载）。
- `Ctrl/Cmd + 点击` → 二期新窗口/分屏，本期忽略。
- 右键行 → 打开与 `⋯` 相同的菜单（触屏长按 500ms 等效）。

### 5.4 列表键盘导航

| 键 | 行为 |
|---|---|
| `↑ / ↓` | 在会话行间移动焦点（仅列表聚焦时） |
| `Enter` / `Space` | 打开聚焦的会话 |
| `F2` | 重命名聚焦行 |
| `Delete` | 打开删除确认（聚焦行） |
| `Shift + F10` / `Menu` 键 | 打开该行 `⋯` 菜单 |
| `Home / End` | 列表首/尾 |
| `Tab` | 依次进入 每行的 `⋯`、再回到 ② 搜索框（列表内 `⋯` 不参与 Tab 序列，改用 `Shift+F10`，避免 1000 条会话产生 2000 个 Tab 停留点） |

> 这条 Tab 策略是刻意的：行数可上千，`⋯` 不进入 Tab 序列才能保证键盘用户不被困住。可访问性通过行上的 `aria-haspopup="menu"` + `Shift+F10` 补齐。

### 5.5 排序跳变抑制

流式生成结束会使 `updated_at` 变化，导致行在列表里跳动。规则：**流式过程中不重排**；流式结束（或中断）后，若该行不在首位，则以 200ms 的位移过渡平滑上移，并短暂（600ms）高亮该行一次。用户正在该行上操作（悬停/编辑/菜单打开）时，**本次不重排**，留到下次列表刷新。

### 5.6 性能

- 消息与会话数可能过千：列表虚拟滚动（固定行高 36px + 分组头高度可计算），只渲染视口 ± 10 行。
- 行内不渲染图片资源（无头像），虚拟滚动的行高恒定，滚动条不会抖动。
- 列表数据订阅走 IPC 增量更新（新增/改名/删除/归档状态），不做整表重取。

## 7. 交互状态与文案清单

| 场景 | 反馈方式 | 文案 |
|---|---|---|

| 删除当前会话 | 焦点转移 | 无 toast |

| 创建/编辑 API Key 失败 | **弹窗内联错误**（不关弹窗） | `入参校验失败：…` 等主进程原文；已填内容一律保留 |
| 删除 API Key 确认 | 模态对话框 | `删除 API Key？` / `删除后密钥一并丢弃，无法恢复。` / `绑定到这条配置的会话会被解除绑定（历史消息保留）。` |

## 9. 自适应规则

| 窗口宽度 | 行为 |
|---|---|
| ≥ 1200px | 三栏可同时存在（详情栏展开时主区仍 ≥ 640px） |
| 900–1200px | 详情栏打开时**覆盖**主区右缘（overlay），不挤压消息宽度 |
| 720–900px | 侧栏自动收起为 56px 图标栏，可手动拉出为浮层侧栏 |
| < 720px | 侧栏一律浮层（overlay + 半透明遮罩），主区独占 |

**宽度只有两态**：展开 260px / 收起 56px（浮层模式下的展开宽度同为 260px），由折叠钮、双击品牌行或 `⌘B / Ctrl+B` 切换；**没有拖拽调宽，也不存在中间宽度**（P10），因此不需要把宽度写进 `app_settings`——只需要记一个布尔量（是否收起）。

高窗口约束：窗口高度 < 560px 时，③ 导航组标题与 ⑥ 底部人设行隐藏，只保留图标导航与列表。

## 10. 无障碍与输入方式

- 全流程键盘可达（第 4.5 / 5.4 节为准）；焦点环永不隐藏（只用 `:focus-visible` 控制出现时机）。
- 悬停/点击菜单**不是唯一路径**：`Shift+F10`、右键、长按三种等效入口。
- `aria-label`：会话行 = `对话：<标题>`；`⋯` = `更多操作：<标题>`；当前会话加 `aria-current="true"`。
- 破坏性操作有确认；重命名/删除结果通过 `aria-live="polite"` 播报，不夺焦点。
- 触屏：行高提升到 44px（`@media (pointer: coarse)`），长按 500ms 打开菜单，禁用悬停态样式。

│   ├── <NavList>                   // ③ 角色库 / 人设 / API Key / 设置

│   ├── <ConversationList>          // ⑤ 虚拟滚动 + 分组
│   │   ├── <ConversationGroup>
│   │   └── <ConversationRow>       // 行 + ⋯ + 行内重命名态
│   └── <SidebarFooter>             // ⑥ 默认人设
├── <MainPane>                      // 按 view 切换下面三者之一
│   ├── <ChatView>                  // 聊天：<ChatTopBar> + <MessageList> + <Composer>
│   ├── <CharactersPage> / <PersonasPage>
│   └── <ApiKeysPage>               // 列表 + <ScrimDialog> 表单弹窗
├── <DetailPanel>                   // 右侧，默认收起（仅对话视图）
└── <OverlayLayer>                  // 菜单 Portal / 删除确认 / 表单弹窗 / toast
```

状态归属建议：`menuState: { conversationId, anchorRect } | null` 放在 Shell 层单一实例（保证"同一时刻只有一个菜单"，且滚轮关闭逻辑只写一处），而非每个 `ConversationRow` 各自持有。

## 13. 验收清单（可直接转成 UI 测试用例）

1. 悬停会话行：背景变化且 `⋯` 出现；指针移出后 180ms 内 `⋯` 消失。
2. 悬停/离开过程中，标题与 `⋯` 的 `getBoundingClientRect()` 不变（无位移）。
3. 点击 `⋯` 出现菜单，含「重命名 / 置顶 / 删除」三项；已置顶会话显示「取消置顶」；删除为危险色。
4. 菜单在视口右/下边缘自动翻转对齐，不被侧栏裁切。
5. `Esc` 关闭菜单且焦点回到该行 `⋯`；点击菜单外任意处关闭。
6. 指针从行移入菜单再回到同一行，菜单全程不关闭。
7. 悬停另一行并点其 `⋯`，菜单锚点切换且无闪断。
8. 「重命名」进入行内输入框且文本全选；`Esc` 回滚；空标题不提交且有可访问提示。
9. 重命名成功后，主区顶栏标题同步，列表顺序不变。
10. 「删除」弹出确认，展示消息数与受影响摘要段数；默认焦点在「取消」。
11. 确认删除后会话、消息、摘要一并消失（事务）；取消则完全不变。
12. 删除当前会话后焦点落到相邻会话；删空后进入空态。
13. 生成中删除会先中断流式，无残留"生成中"状态。
14. `⌘K` 聚焦搜索，输入后列表即时过滤并改为一行「找到 N 个对话」，`Esc` 清空。
15. 列表键盘导航：`↑/↓`、`Enter`、`F2`、`Delete`、`Shift+F10` 全部生效。
16. 行内 `⋯` 不在 Tab 序列中（1000 条会话时 Tab 次数不随行数增长）。
17. 流式结束后行平滑上移一次并短暂高亮；用户正在操作该行时不重排。
18. 窗口宽度 < 720px 时侧栏转为浮层，主区不被压到 480px 以下。
19. 侧栏折叠到 56px 后，四个导航与新对话仍可点击并有 tooltip。
20. 深色主题下 `⋯`、菜单阴影、选中条对比度 ≥ 3:1（文字 ≥ 4.5:1）。
21. 置顶后该会话进入「已置顶」段首位，且其 `updated_at` 未变；取消置顶后回到其余会话中它该在的位置（按 `updated_at DESC`）。
22. 会话界面（主区 + 右侧栏）的验收见 `docs/ui-design-conversation.md` 第 12 节。
23. 列表**不出现任何时间分组标题**：`今天 / 昨天 / 前 7 天 / 更早` 这些文案在 DOM 中的出现次数为 0；无置顶会话时列表内一个分组标题都没有。
24. 侧栏宽度只有 260px 与 56px 两种取值：折叠钮 / 双击品牌行 / `⌘B` 切换后 `getBoundingClientRect().width` 必须是这两个值之一；侧栏边缘不存在任何以调宽为目的的命中区（宽度拖拽交互整体不存在）。
25. **消息相关界面**不存在头像元素：会话行、消息、空态、右栏角色标签内的 `img`/头像容器数量为 0，身份信息全部来自文本。（**角色库除外**——它是卡片网格，见勘误与验收项 29。）
26. 消息流中不存在"已归档"文案；归档消息只以 `opacity` 降低区分（对比度不低于 3:1，仍需可读）。
27. 点会话行**总是**回到对话视图：在角色库 / 人设 / 设置页点任意会话行（含"点的就是当前已选中那个"）之后，主区必须显示对话界面；视图为对话时 ③ 导航里没有任何 `aria-current=page`。
28. 「新对话」不直接建会话，而是打开三步向导（选角色 → 选人设 → 选 Key），每步都要显式确认，**确认之前库里不新增会话**。从角色卡的「新对话」进入时跳过第 1 步。第 3 步只列**启用**的 Provider 并显示其是否已存密钥；没有任何可用 Provider 时「开始对话」禁用并给出「去设置」。
29. 角色库是**卡片网格**：每张卡是 2:3 竖版（`aspect-ratio`），上面图片、下面名字；**卡片内不出现描述文本**；没有图片的卡渲染灰色占位块而不渲染 `img`；网格列宽自适应而不是固定列数。
30. 点角色卡打开**详情弹窗**，弹窗内含全部动作（新对话 / 编辑 / 收藏 / 导出 / 删除 / 关闭）；Esc 与点遮罩可关；执行新对话 / 编辑 / 删除后弹窗自动关闭；收藏后弹窗状态跟随刷新（不显示旧值）。
31. 新建会话的**默认标题是角色名**，重名则依次为 `<名> 2`、`<名> 3`……；重名判断是全库的；用户手动改过的标题不被改写。
32. 不在对话视图时，会话行**不显示选中态**（无 `.active`、无 `aria-current`），但当前会话本身保留——回到对话视图后仍是它。
33. 导入 PNG 角色卡：`导入角色卡` 对话框接受 `png`；导入一张真卡后角色出现在网格里**并显示卡面图**（不再走灰色占位块），头像文件落在 `<userData>/avatars/<角色 id>.png` 且内容与源 PNG 一致；同一张卡导入两次得到两张独立的卡与两个独立的头像文件，互不覆盖。普通 PNG（不含 `chara`/`ccv3` 文本块）被拒时给出可读原因，而不是导入一个空角色。
34. 详情弹窗的「导出」**先开格式菜单**（`导出为 JSON` / `导出为 PNG 卡`），**不选格式就不发起导出**；没有卡面图的角色，PNG 项置灰且写明原因。选 PNG 卡导出后，文件里是**原卡面图逐字节未变 + 新数据**（文本块只剩一个，旧的 `chara`/`ccv3` 已被替换），并且能被重新导入。
35. 多层浮层的 `Esc` 只关**栈顶**那一层：导出菜单开着时按 `Esc`，菜单收起而详情弹窗仍在；再按一次才关弹窗。
36. 导航含**「API Key」**项，点击切到该视图并带 `aria-current=page`。
37. **API Key 页是列表 + 弹窗**：页面上不出现任何常驻表单（未打开弹窗时 `名称` / `base_url` 输入框数量为 0）；点「创建 API Key」或行内编辑才出现弹窗，Esc / 点遮罩 / 「取消」都能关闭。
38. **密钥列只渲染固定掩码**，不含真 Key 的任何片段（`hasKey` 为假时显示「未配置 Key」）；「最新使用日期」来自消息元数据，从未用过显示「—」。删除 Key 必须先过确认框，且文案说明"密钥一并丢弃 + 会话解除绑定"。
39. **设置页只剩三段**：全局默认 / 生成与行为 / 诊断。`Provider 与密钥`、常驻的添加表单、「导出明文配置包」入口在设置页的 DOM 中出现次数为 **0**。

## 14. 明确不做（避免界面膨胀）

- 会话多选 / 批量删除 / 批量导出（后台任务型交互，与"简约"冲突）。
- 会话文件夹、嵌套分组、自定义排序拖拽（MVP 只分「已置顶」与其余，其余按时间倒序）。
- **左右栏拖拽调宽**（只保留拉出/收起两态，见 P10）。
- **任何位置的头像位**（消息、列表、空态、右栏一律不放，见 P9）。**唯一例外是角色库的卡片与它的详情弹窗**（浏览型界面，见 §3 勘误）。
- 列表项上直接放收藏、导出、复制图标（一律进 `⋯` 或详情栏）。
- 主区顶栏放"分享/更多"等次级动作。
- 侧栏放统计图、token 总量、费用小卡片（这些属于详情栏与设置页）。

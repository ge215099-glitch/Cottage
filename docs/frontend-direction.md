# 前端重设计方向

状态：第一轮实现依据，2026-11-18；具体完成与待验收项见 [实现记录](implementation-status.md)。用户已确定的目标：AI 角色聊天、参考 FrontendDemo 的 ChatGPT 简约风格、简化右侧栏。以下具体交互用于下一步原型，不冒充已获逐项确认的需求。

## 1. 设计原则

让角色对话成为视觉中心。用留白、正文排版、轻量导航和少量按需入口表达功能；简约应体现在信息量和操作路径，而不只是换一套颜色。

demo 是主要审美依据。沿用它的白/浅灰底、柔和选中态、细线图标、低对比分隔与圆角输入框；支持对应的深色主题。保持适合中文长文阅读的字体，不为满足设计 skill 的通用建议强行替换成装饰字体。

暂不增加语音、附件、登录、订阅、分享链接等 demo 外观中暗示、但现有业务没有的功能。

## 2. 主界面

```text
┌─────────────────┬─────────────────────────────────────────┐
│ Cottage    收起 │ 角色/会话名称   模型选择           更多 ⋯ │
│                 │                                         │
│ 新对话          │                                         │
│ 搜索对话        │          居中的角色消息正文               │
│ 角色库          │                                         │
│                 │                      浅灰用户消息气泡   │
│ 已置顶 / 对话   │                                         │
│ 会话列表        │                                         │
│                 │        ┌───────────────────────┐        │
│                 │        │ 输入消息         发送 │        │
│ 设置            │        └───────────────────────┘        │
└─────────────────┴─────────────────────────────────────────┘
```

此图只表达信息分布，不是最终像素稿。默认无右栏、无彩色 token 分段条、无参数表单。

- 左栏承担新建、搜索、角色库和会话切换；设置留在底部。
- 人设、API 连接和用量归入设置的清晰分类，避免左栏常驻五个管理页面入口。
- 顶栏呈现当前角色/会话、实际生效模型和一个更多菜单。不把身份、模型和会话标题堆成多行仪表盘。
- 消息正文和输入区共用阅读中轴。角色消息不包大卡片；用户消息用浅色气泡；角色卡图片留在角色库与详情中。
- 导入失败、密钥缺失、生成错误在相关位置给出明确下一步，不能只弹瞬间消失的提示。

会话列表暂沿用“已置顶 + 其余会话”的两段结构。demo 的日期分组属于可参考交互，不因外观相似而强行更换旧数据语义。

## 3. 原右栏功能的新位置

| 原功能 | 新入口 | 默认呈现 |
|---|---|---|
| 当前模型/Provider | 顶栏模型选择器；按连接分组 | 只显示实际生效模型；未配置时给“配置模型” |
| 当前用户人设 | 会话更多菜单 → 对话设置 | 显示选择项，管理入口进入设置 |
| temperature/top_p/max_tokens | 对话设置 → 高级生成参数 | 折叠；可恢复继承默认值 |
| 角色资料 | 点击角色名/更多菜单 → 角色资料 | 按需详情，编辑进入角色编辑器 |
| 上下文占用 | 更多菜单 → 对话记忆；临近上限时输入区轻提示 | 正常时不展示详细数字 |
| 手动压缩、摘要历史、恢复 | 对话记忆面板 | 首屏只放概况和整理动作；历史、技术明细展开查看 |
| 自动压缩开关与阈值 | 设置 → 对话与记忆 | 显示真实保存值，不在聊天页重复表单 |
| 本次/历史 token 用量 | 设置 → 用量 | 从本地记录取值，不展示虚构账单 |
| 导出 Markdown/JSON、复制全文 | 会话更多菜单 | 菜单中的独立操作 |
| 重命名、置顶 | 左侧会话菜单；重命名可保留快捷交互 | 选中态保持安静，不堆常驻按钮 |
| 用开场白重开、删除 | 会话更多菜单底部 | 二次确认，说明会清除的内容与数量 |

不要把这张表机械变成一个超长菜单。更多菜单的一级项控制为：对话设置、角色资料、对话记忆、导出、重开/删除；改名与置顶优先留在左侧会话菜单。复制全文可放导出子菜单。

## 4. 对话记忆面板

采用按需打开的轻量面板；可在宽屏使用覆盖式抽屉，窄屏改为近全屏弹层。它不应挤压正文成为默认三栏，也不继承旧版四标签结构。

首屏只回答：

1. 当前对话是否还有空间，以及这个判断是否基于估算。
2. 是否已开启自动整理，当前是否正在整理。
3. 用户现在是否需要手动整理。

摘要历史逐条展开，可查看覆盖区间、摘要正文和恢复操作。精确/估算 token、分段明细放到“技术明细”折叠区。术语首次出现解释为“将较早消息整理为摘要，原文仍保留”。

压缩中的状态必须来自主进程事件，不因关闭面板消失。取消只有在主进程实际支持时才出现；关闭面板仅代表关闭视图。目前没有压缩取消入口。失败保持原历史可用，并给重试入口。

## 5. 关键流程与状态

| 情境 | 预期行为 |
|---|---|
| 第一次进入 | 友好空态，主动作是选择/导入角色；若模型未配置，给明确配置入口 |
| 从角色库开始 | 使用默认模型与人设直接建立会话；缺必填配置时再补选，不强制每次四步向导 |
| 输入 | 多行自适应；Enter 发送、Shift+Enter 换行；尊重用户 Ctrl+Enter 设置与中文输入法组合状态 |
| 发送 | 立即展示用户消息与生成状态；正常流式更新；空正文不是静默成功 |
| 发送前失败 | 保留或恢复草稿；明确说明连接、密钥或上下文问题 |
| 生成中 | 发送按钮变停止；切换页面不串流；停止后保留已有内容 |
| 滚动 | 用户查看旧消息时不抢滚动，提供回到最新按钮 |
| 消息操作 | 悬停/键盘焦点时出现复制、重生成、更多；触屏有可发现入口 |
| 修改历史 | 明确说明后续消息和摘要的影响；需要截断时先确认 |
| 打开/关闭设置 | 草稿和消息滚动位置稳定；Esc 关闭并把焦点还给入口 |
| 重开/删除 | 用清楚的确认文案说明影响，不能用含混的“确定吗” |

不在聊天中切换绑定角色来偷偷改变整段历史含义。更换角色优先开启新会话。

## 6. 初始视觉参数

参数是实现起点，可按真实窗口验证微调。

| 项目 | 初值 |
|---|---|
| 左栏 | 260px；可收起，窄屏作为抽屉 |
| 正文区域 | 最大约 800px，实际文字宽度扣除水平内边距 |
| 输入区 | 最大约 768px，与消息阅读区视觉对齐 |
| 浅色 | 主底 #ffffff，左栏 #f9f9f9，正文 #0d0d0d，用户气泡 #f4f4f4 |
| 深色 | 参考 demo：主底 #212121，左栏 #171717，输入区/气泡 #303030 |
| 中文正文 | 约 16px，行高约 1.7–1.8 |
| 图标/动效 | 细线图标；约 120–200ms 的轻过渡；尊重减少动态效果偏好 |

不在每条消息下常驻时间戳、token、耗时、参数和状态标签。技术细节应帮助排查问题，而不是干扰角色对话。

## 7. 界面验收

- 1440×900 和 1280×800 默认聊天页无右侧管理栏，正文不被挤窄。
- 900px 以下侧栏按需覆盖，关闭后保留当前会话和草稿；同时遵守实际桌面窗口最小尺寸。
- 首屏只有少量导航与明确聊天动作，展开高级功能前不出现参数密集表单。
- 浅色、深色、长角色名、长模型名、长文本、代码块与表格均可阅读，无横向撑破。
- 键盘可完成模型选择、菜单、发送、停止与面板关闭；焦点可见，弹层焦点范围与恢复正确。
- 界面精简之后，旧版的角色卡、密钥管理、导出与压缩恢复仍可找到并完成。
- 以上布局项必须在实际渲染窗口检查；不能用组件测试通过替代。

# Cottage 界面与交互设计：对话界面（主区 + 右侧栏）

> 版本：v1.0（MVP）
> 上游基线：`docs/product-design.md` v1.0（3.3 / 3.4 / 3.5 / 3.6 / 3.8）；左栏规范见 `docs/ui-design-sidebar-chat.md`
> 本文回答一个问题：**聊天的时候，界面上的东西放在哪、什么时候出现。**
> 一句话结论：**主区只负责"聊天"，右栏只负责"看清这次对话的成本与配置"，其余一切进对话框。**

---

## 1. 为什么右栏该存在（先定职责，再画图）

`product-design.md` 3.6 给右栏列了 9 项职责。如果照单全收做成一列，它会长成一个 700px 高的滚动设置页——聊天时右栏一直在旁边，这是最吵的做法。

所以先做一次**职责分流**，判断标准只有一条：*这件事用户是"一边聊一边要"的，还是"聊之前/聊之后配置的"？*

| 原 3.6 项 | 归类 | 去处 |
|---|---|---|
| ① 上下文占用 + Token 明细 | 边聊边要 | **右栏「上下文」** |
| ③ 压缩按钮 + 压缩历史查看/恢复 | 边聊边要 | **右栏「上下文」** |
| ⑨ 删除某几条历史 | 边聊边要（低频） | 消息悬浮工具条 → `⋯` |
| ⑤ 切换 Provider / Key / 模型 | 低频配置 | **右栏「对话」**（留在手边但收在标签页里） |
| ⑥ 生成参数调节 | 低频配置 | **右栏「对话」** |
| ② 本次消耗（用时/tokens/费用） | 事后核对 | 消息气泡底部（已有）+ 右栏「上下文」汇总 |
| ④ 角色卡信息预览 + 编辑 | 配置 | 右栏「角色」；**编辑**进全屏/大对话框 |
| ⑦ 开场白切换器 | 一次性 | 空态页 + 输入区 `⋯`（重开/换开场白） |
| ⑧ 导出当前会话 | 事后 | 右栏「数据」；也可从左栏 `⋯` 进 |

分流后，**常驻可见的信息只剩三样：这次对话用谁在聊、上下文还剩多少、这一轮花了多少。** 其余都收进标签页或对话框。这就是右栏不会变乱的原因。

## 2. 对比过的三种布局方案

| 方案 | 形态 | 优点 | 致命问题 | 结论 |
|---|---|---|---|---|
| A 纯按钮 + 抽屉 | 主区顶栏一排按钮，点开才拉出右抽屉 | 主区最宽 | 占用条与压缩状态看不见，"聊到爆上下文"是 Cottage 的核心场景，最该看见的东西反而被藏起来；顶栏按钮一多就回到"乱七八糟" | 否 |
| B 主区顶栏 + 右栏只放设置 | 右栏=配置项 | 配置集中 | 与聊天同时要看的信息（占用/摘要）被挤到别处；右栏变成滚动设置页 | 否 |
| **C（采用）分标签右栏 + 常驻占用条** | 右栏 3 个标签（上下文/对话/数据），输入框右下角常驻一行占用与模型 | 边聊边要的信息永远可见；配置不挤占视觉；标签切换零成本 | 标签页本身是一层认知负担 → 用**默认标签 + 记忆上次标签 + ⌘1/2/3** 抵掉 | **采用** |
| C' 单列手风琴（不做标签） | 右栏一列可折叠段 | 无标签 | 段落多时仍要滚动找；折叠状态记忆复杂 | 备选，若实测标签切换频繁再降级为 C' |

方案 C 的关键设计是**"占用条下沉到输入框角落"**：它不占主区垂直空间（不新增工具栏，也没挤进顶栏），但用户每轮输入都会看到它。右栏关闭时也不丢信息。

## 3. 对话界面整体骨架

```
┌────────────┬──────────────────────────────────────────────┬──────────────────┐
│ 左侧栏      │ 主区 Main                                     │ 右栏 DetailPanel  │
│ 展开 260px  │ flex:1  min 480px                             │ 展开 320px        │
│ (另文档)    │                                               │ 收起 = 不占位      │
└────────────┴──────────────────────────────────────────────┴──────────────────┘
```

> **左右栏都不可拖拽调宽**：只有展开 / 收起两态（见 `docs/ui-design-sidebar-chat.md` P10）。右侧栏在窄窗口下改为覆盖式抽屉——这也是"拉出/收起"，不是调宽。
> **界面不使用头像**：消息、会话列表、空态、右栏角色卡一律不加头像，说话人由**名字文本**（12px 次要色）标识（P9）。
> 唯一例外是**角色库**——它是卡片网格（上面图片、下面名字），因为浏览型界面靠图识别最快；
> 详见 `docs/ui-design-sidebar-chat.md` 的 v1.1 勘误。消息相关界面仍然无图。

### 3.1 主区

```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏 48px   夜巡酒馆的第三夜 ✎                     [📌][⧉ 详情 ⌘I]    │ ← 📌 仅悬停显示
├──────────────────────────────────────────────────────────────────────┤
│ 消息流（唯一滚动区，内容宽 720px 居中）                                │
│                                                                      │
│                  ┌ 已压缩 第 3–15 条 ┐  ← 摘要分割条（点击展开原文）    │
│                                                                      │
│   酒保                                        ← 角色名（12px 次要色）    │
│   ────────────────────────────────────   ← 角色消息：无气泡，全宽文本   │
│   左对齐，无头像，紧接名字下方                                          │
│                                                    [⧉][✎][↻][⋯] ───  │ ← 悬停消息才出现
│                                                                      │
│                                        ┌────────────────────────────┐ │
│                                        │ 用户消息（浅填充气泡，右对齐）│ │
│                                        └────────────────────────────┘ │
│                                             [⧉][✎][⋯] ────────────   │
│                                                                      │
│   [ 已中断 ]  18.4s · 512 tok · 精确  ← 元信息 12px 次要色，仅悬停/错误时显示│
├──────────────────────────────────────────────────────────────────────┤
│ 输入区（不滚动，居中 720px）                                          │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │ 多行输入（1→8 行自适应），Enter 发送 / Shift+Enter 换行          │  │
│  │                                                                │  │
│  │  [Claude ▾]  [temp .9 ▾]  [人设 ASMobbin ▾]        上下文 62% ▏ │  │
│  │                                          [ 停止 ⏹ ] / [ 发送 ↑ ] │  │
│  └────────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────┘
```

三处刻意的克制：

1. **顶栏只 2 个元素**（标题、详情开关）。置顶按钮只在鼠标进入顶栏时淡入，且 `📌` 状态常驻可见（否则用户看不出置顶了）。
2. **模型 / 温度 / 人设不用三个下拉常驻**：输入区那一行左半边默认只显示 **一个** `模型 ▾`（最高频），温度与人设收进它右侧的 `⋯`（会话配置）里；三个 chip 只在用户打开过该会话的配置后才常驻（记忆化）。中文界面上三个下拉并排 = 视觉噪音（P1）。
3. **消息操作条只在悬停该条消息时出现**，且 `⋯` 是同一套菜单组件（复用左栏的 Portal 菜单实现）。

### 3.2 右栏（默认打开，记忆上次状态）

```
┌──────────────────────────────┐
│ 上下文 │ 对话 │ 数据          │ ← 标签 32px，选中项为文字强调+底部 2px 线
├──────────────────────────────┤
│ ⟳ 自动压缩 已开         [改] │ ← 一行摘要，点击跳到设置对应项
│                              │
│ 上下文占用              62%  │
│ ████████████░░░░░░░          │ ← 6px 圆角条；≥75% 转琥珀色
│ 12,400 / 20,000 tok  精确 ✓  │ ← 估算时显示"约"（3.3 要求）
│                              │
│ 明细                          │
│  system        820    ▎      │
│  few-shot      460    ▏      │
│  摘要(4 段)   1,180   ▎      │
│  历史(86 条)  8,940   █▎     │
│  本次输入       200   ▏      │
│  ─────────────────────────   │
│  合计        12,400          │
│                              │
│ ┌──────────────────────────┐ │
│ │  压缩最老的 8 条 (约省 2.1k)│ │ ← 主按钮（唯一实心），仅在不忙时可用
│ └──────────────────────────┘ │
│  压缩历史 · 4 段         [展开]│
│   ├ 第 3–15 条 1,200→180  [恢复]│ ← 展开后每条右侧才出现"恢复"
│   ├ 第 16–34 条 2,050→210 [恢复]│
│                              │
│ 本次消耗                       │
│  用时 18.4s · 512 tok · $0.003│
│  TTFT 640ms                  │
└──────────────────────────────┘
   ↑ 「对话」标签：Provider/Key/模型、temperature/top_p/max_tokens、
     persona、开场白重开      ↑ 「数据」标签：导出 MD/JSON、复制会话、
     删除会话（危险区）、统计（条数、摘要段数、创建/更新时间）
```

右栏的三条硬规则：

- **R1 不新增右栏专属入口**：右栏的开关只在主区顶栏（`⌘I`）与输入区占用数字两处，左栏不加按钮。
- **R2 每个标签首屏不滚动**：上下文 ≈ 420px、对话 ≈ 360px、数据 ≈ 280px，都在常见窗口高度内免滚动；超长内容才滚，且标签头吸顶。
- **R3 压缩是状态机**：空闲=实心按钮；压缩中=按钮变进度（`压缩中 3/8 段…`）+ 可取消；失败=按钮位置变错误条（原因+重试）；成功后**内联播报**（`已将第 3–15 条压缩（1,200 → 180 tokens）`），并在消息流对应位置插入摘要分割条（见 3.1）。

## 4. 消息流规格（3.5 的界面落地）

| 元素 | 规格 |
|---|---|
| 角色消息 | 无气泡。角色名（12px 次要色，**无头像**）单独一行 + 全宽文本（15px/26px），最大内容宽 720px |
| 用户消息 | 浅填充气泡、右对齐、圆角 12px、最大宽 560px（长文本不铺满整行）。用户消息不显示名字 |
| 消息间距 | 同角色连续消息 8px；换角色 24px（留白分组，不加分隔线） |
| 悬停工具条 | 消息右上（用户消息为左上）：`复制` `编辑` `重新生成`（仅最后一条角色消息） `⋯`（删除此条/删除以下） |
| 生成中 | 角色消息末尾 2px 强调色光标闪烁；工具条替换为「停止」（与输入区发送键同一动作） |
| 中断 | 气泡下方 `已中断` 灰色标签 + 「继续」按钮（保留部分内容，3.5 要求） |
| 元信息 | 12px 次要色，**默认隐藏**，悬停该消息或全局开关打开时显示：model、用时、prompt/completion tokens、精确/估算 |
| 错误 | 该条消息下方错误条：原因 + `重试`；429 显示 `重试中(1/2)`（3.8 表格） |
| 摘要分割条 | 全宽细线 + 居中胶囊 `已压缩 第 3–15 条 ⌄`；展开后在原位显示归档原文（灰底），右侧 `恢复`。归档消息**只以轻微降透明度区分，不加"已归档"标签** |
| 滚动行为 | 生成中**粘底**；用户手动上滚后停止粘底，右下出现 `↓ 回到最新`（不自动跳，3.5 用户体验） |

消息的三个规则：

1. **编辑用户消息** → 行内变文本域 + 底部一行询问 `截断后续消息？`（两个按钮：`仅保存` / `保存并截断`）。落在摘要区间时提示会被级联失效（3.5 冲突规则），提示文案：`此操作会使 1 段摘要失效并被删除`。
2. **重新生成**就地替换该助手消息（MVP 不做多候选，3.5 明确）。
3. **删除消息**走确认轻量弹层（与删除会话同一组件，文案不同），删除区间触及摘要时同样级联失效。

## 5. 输入区规格

| 部位 | 规格 |
|---|---|
| 高度 | 1 行 44px → 最多 8 行（约 200px）后内部滚动 |
| 发送 | `Enter` 发送（设置可切换 `Ctrl+Enter`）、`Shift+Enter` 换行；按钮同一位置在生成中变「停止」 |
| 模型 chip | 显示当前模型短名 + `▾`；下拉含 Provider/Key/模型 + `跳到设置`；切换即时生效于下一条消息（不改历史 metadata） |
| 占用数字 | `上下文 62%`；≥75% 琥珀、≥80% 红并提示 `已自动压缩`；点击 = 打开右栏「上下文」标签 |
| 空态 | 无消息时输入区居中靠下，上方显示**角色名**（大字 20px，无头像）与开场白；开场白有多个时下方一排小胶囊切换（最多显示 6 个，多余进 `⋯`） |
| 拖入文件 | 本期不导入附件（MVP 边界），拖入显示"暂不支持"轻提示 |
| 无 Key 时 | 输入框可输入但发送禁用，下方提示 `还没有可用的 API Key` + `去 API Key` 跳转按钮（3.8 401/403 的前置态；Provider 与密钥的增删改在导航模块「API Key」里） |

## 6. 功能入口总表（"哪个功能放哪里"的唯一答案）

> 标记说明：**M**=MVP 必须；**L**=二期。任何未列在此表的功能，默认不做。

| 功能 | 入口位置 | 阶段 |
|---|---|---|
| 新建对话 | 左栏 ② 主按钮 | M |
| 切换会话 | 左栏列表单击 | M |
| 重命名 / 置顶 / 删除会话 | 左栏会话行 `⋯`；置顶也可用顶栏 `📌` | M |
| 搜索会话 | 左栏 ② / `⌘K` | M |
| 打开右栏 | 顶栏 `⧉ 详情` / `⌘I` / 输入区占用数字 | M |
| 看上下文占用与明细 | 右栏「上下文」 | M |
| 手动压缩 / 压缩历史 / 恢复 | 右栏「上下文」 | M |
| 自动压缩开关 | 右栏「上下文」首行 ← 跳设置 | M |
| 切换 Provider / Key / 模型 | 输入区 `模型 ▾`（高频）/ 右栏「对话」 | M |
| temperature / top_p / max_tokens | 右栏「对话」（会话级覆盖） | M |
| 切换 persona | 右栏「对话」；左栏底部为全局默认 | M |
| 换开场白 / 重开会话 | 输入区 `⋯`；空态页胶囊 | M |
| 查看角色卡信息 | 右栏「角色」（新增第 4 个入口，见下注） | M |
| 编辑角色卡 | 角色卡信息板底部 `编辑` → 大对话框 | M |
| 复制消息 / 编辑消息 / 重新生成 | 消息悬停工具条 | M |
| 删除消息 / 删除以下 | 消息 `⋯` | M |
| 导出 MD / JSON | 右栏「数据」 | M |
| 复制整段会话 | 右栏「数据」 | M |
| 删除当前会话 | 右栏「数据」危险区 + 左栏 `⋯` | M |
| 耗时 / tokens / 费用 / TTFT | 消息元信息 + 右栏「上下文」汇总 | M |
| 回到最新 | 消息流右下浮起按钮 | M |
| 全局默认 Provider/Key/模型、压缩默认 | 设置页 | M |
| 多候选重新生成 / 消息分支 | — | L（3.5 明确不做） |
| 消息搜索（会话内） | — | L |
| 附件 / 图片输入 | — | L（MVP 边界） |

> 注：右栏因此是 **4 个标签**（上下文 / 对话 / 角色 / 数据）。角色标签内容是只读预览（名称、tags、描述摘要 + `编辑`，**不放头像**），所以视觉上仍轻。若实测认为 4 个标签偏多，可将「角色」并入「对话」标签底部。

## 8. 自适应与快捷布局

| 窗口宽度 | 右栏行为 |
|---|---|
| ≥ 1280px | 右栏**并排**，主区消息仍 ≥ 720px |
| 1024–1280px | 右栏并排，固定 290px，消息内容允许降到 640px 居中 |
| 720–1024px | 右栏改为**覆盖式抽屉**（从右侧滑出 320px，带 8px 阴影，不遮左栏），主区宽度不变 |
| < 720px | 左栏已是浮层（另文档），右栏为全宽抽屉；打开右栏时输入区保持可见（不弹全屏） |

**右栏宽度固定 320px（窄档 290px），不可拖拽**：`⌘I` / 顶栏 `⧉` / 输入区占用数字三处开关，展开时以 160ms 滑入动画出现。收起即不占位（`display:none`），因此不需要记忆宽度，只需要记忆"上次是否打开 + 上次在哪个标签"。

| 快捷键 | 行为 |
|---|---|
| `⌘/Ctrl + I` | 开/关右栏 |
| `⌘/Ctrl + 1/2/3/4` | 右栏标签页（右栏打开时） |
| `⌘/Ctrl + Enter` | 发送（当设置为 Ctrl+Enter 模式） |
| `Esc` | 关闭菜单/对话框 → 停止生成（生成中最后一道） |
| `⌘/Ctrl + Shift + C` | 复制最后一条角色消息 |
| `End` / `⌘↓` | 回到最新 |

## 9. 会话置顶的数据与行为约定

### 9.1 数据（对 `product-design.md` 第 4 节的增补）

```
conversations(id, title, character_id, persona_id, provider_id, model,
              params_json, pinned_at, created_at, updated_at)
                                 ↑ 新增：NULL = 未置顶；非空 = 置顶时刻（INTEGER，毫秒）
```

- 排序：`ORDER BY pinned_at IS NOT NULL DESC, COALESCE(pinned_at, 0) DESC, updated_at DESC`。
- 索引：`conversations(pinned_at DESC)`（配合已有 `conversations(updated_at DESC)`）。
- **写 `pinned_at` 时不更新 `updated_at`**；这一条要落进 DAO 层的测试。否则取消置顶后，一条上个月的会话会因为 `updated_at` 被刷新而跳到列表最前面，把本该在最上面的近期会话挤下去。
- 迁移：新增一条顺序迁移（`ALTER TABLE conversations ADD COLUMN pinned_at INTEGER`），遵守"迁移从第一天存在"（第 4 节约束）。

### 9.2 交互

| 行为 | 细节 |
|---|---|
| 入口 | 左栏 `⋯` → `置顶`/`取消置顶`；主区顶栏 `📌`（悬停顶栏才出现，已置顶时常驻显示实心态） |
| 即时反馈 | 行移动到「已置顶」组首位的位移动画 200ms；无 toast |
| 置顶态视觉 | 行尾在原 `⋯` 左侧多一个 12px 实心图钉？**不做**——用分组位置表达即可，多一个图标就多一分噪音 |
| 上限 | 置顶数不设硬上限；超过 5 条时「已置顶」组可折叠（标题右侧 `⌄`） |
| 与删除 | 删除会话自然带走 `pinned_at` |
| 搜索态 | 过滤结果中置顶项仍排最前，但不显示分组标题 |
| 触屏 | 长按行 → 同菜单，可置顶 |

## 10. 状态与文案清单

| 场景 | 展示 | 文案 |
|---|---|---|
| 自动压缩触发 | 消息流顶部摘要条 + 右栏首屏 | `已将第 3–15 条压缩（1,200 → 180 tokens）` |
| 手动压缩中 | 右栏按钮变进度 | `压缩中 3/8 段…`（可取消） |
| 压缩失败 | 按钮位置变错误条 | `压缩失败：<原因>` + `重试`；**不删摘要、不改归档**（原子性） |
| 恢复归档 | 摘要条原位更新 | `已恢复第 3–15 条，对应摘要已失效` |
| 上下文 ≥ 75% | 占用条转琥珀 | `上下文 76%　接近上限` |
| 自动压缩后仍超限 | 输入区上方错误条 | `上下文仍超出模型上限，请压缩或更换模型`（3.3：明确报错不静默截断） |
| 估算 token | 占用数字前 | `约 12,400 tok（估算）` |
| 流式中断 | 气泡下方 | `已中断` + `继续` |
| 限流重试 | 气泡下方 | `限流，正在重试（1/2）…` |
| Key 无效 | 输入区下方 | `Key 无效或权限不足` + `去设置` |
| 生成中切换会话 | 左栏该行呼吸圆点继续 | 无弹窗、不阻塞 |

## 12. 验收清单（可直接转成 UI 测试用例）

1. 顶栏仅含会话标题与详情开关两个可交互元素（置顶按钮默认不可见）。
2. `⌘I` 开/关右栏；关闭后重新打开回到上次所在标签页；重启应用后状态与宽度被恢复。
3. 输入区占用数字恒显示；点击后右栏打开且停在「上下文」标签。
4. 右栏「上下文」首屏不出现滚动条（高度 720px 及以上窗口，token 明细 ≤ 10 行时）。
5. 占用 75% 时进度条与数字转琥珀色；80% 触发的自动压缩在右栏有具体文案（含条数与 token 变化）。
6. 压缩中按钮变进度且可取消；取消后摘要未写入、归档标记未改变。
7. 压缩失败时错误条出现，数据库摘要表与消息归档标记均无变化（原子性）。
8. 恢复某段摘要后，消息流中对应摘要条消失、归档消息回到历史、占用上升。
9. Token 明细各项之和等于合计；估算模型下数字前有"约"且旁标"估算"。
10. 手动压缩成功后，消息流在对应位置插入 `已压缩 第 3–15 条` 分割条，展开可见灰底归档原文。
11. 角色消息无气泡、用户消息为右对齐气泡；悬停消息出现工具条，移开 180ms 内消失。
12. 消息 `⋯` 菜单与左栏会话 `⋯` 菜单为同一组件（同一定位/关闭/键盘行为）。
13. 生成中：发送键变停止；消息末尾有光标；上滚后出现 `↓ 回到最新` 且不再自动粘底。
14. 停止生成后保留部分内容并显示 `已中断` + `继续`；再次发送不重复插入消息。
15. 编辑用户消息时询问是否截断；选择截断且区间落在摘要内时，提示"会使 1 段摘要失效"并在确认后删除该摘要。
16. 重新生成就地替换该条助手消息，消息总数不变（无新增候选）。
17. 未配置 Key 时发送禁用并给出跳转设置的提示。
18. 1024px 窗口下右栏转为覆盖式抽屉，主区消息宽度不变；≥1280px 时并排。
19. 右栏宽度恒为 320px（1024–1280px 档为 290px）；页面不存在拖拽手柄，`cursor: col-resize` 检索结果为 0；`⌘I` 只在两态间切换且不产生中间宽度。
20. 双击顶栏标题进入行内重命名，与左栏行为一致（Esc 回滚、空标题不提交）。
21. 置顶入口（左栏菜单与顶栏 `📌`）状态同步；置顶后进入「已置顶」组首位。
22. 置顶操作不改变 `updated_at`（DAO 层单测）；取消置顶后该会话回到其余会话中按 `updated_at DESC` 的正确位置（列表不按时间分组，见左栏文档 5.1）。
23. 取消置顶后回到正确的时间分组位置，位移动画 200ms 内完成。
24. 删除当前会话的入口在右栏「数据」与左栏菜单行为一致（同一确认组件）。
25. 界面无头像：消息区、空态、右栏「角色」标签内的头像容器/`img` 数量为 0；角色身份仅由名字文本呈现。
26. 归档消息上不出现"已归档"文案；其文本透明度降低后仍满足对比度 ≥ 4.5:1（正文）。

## 13. 明确不做（避免界面膨胀）

- 主区顶栏放分享/更多/导出/设置等次级动作。
- 输入区常驻三个以上下拉（模型之外的温度、人设默认收起）。
- 右栏做成滚动设置页；任何"聊之前配置一次"的项目（全局默认 Key、压缩默认模型）都留在设置页。
- 右栏放统计图、费用趋势图、token 历史曲线。
- **右栏拖拽调宽**（只保留展开/收起两态）。
- **消息、空态与右栏的头像**；归档消息上的"已归档"标签。
- 消息级附件、图片、语音按钮（MVP 边界）。
- 消息分支 / 多候选切换 UI（3.5 明确不做）。
- 会话内全文搜索（L）。
